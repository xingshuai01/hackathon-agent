## 一、已敲定的决策

### 产品方向

#### DEC-001 · 产品形态
- **决策**:做**科研 Agent**,创新点是三个科研领域模块:**个人知识库 / 工具库 / 技能库**
- **备选**:① 纯论文综述生成器 ② 实验记录 Agent ③ 系统性综述 Agent
- **理由**:比赛题目要求。三个模块是"新增功能",即卖点,必须各自可独立演示
- **日期**:2026-10-27
- **影响**:SRS `D-01` `D-02`

#### DEC-002 · 三个模块的关系
- **决策**:三个模块是**「沉淀层」的三层**,不是一条流水线的三步;既有「沉淀」方向(论文→资产),也有「消费」方向(任务→复用资产)
- **备选**:把三个模块当流水线三步,只保留最后一步产物(综述报告)
- **理由**:若当流水线,前两步的产物不可见,卖点就没了。双向闭环才是创新点的技术表达
- **日期**:2026-10-27
- **备注**:这是对 SRS v1.0 的修正,v1.0 做错了这一点
- **影响**:SRS `D-02`、§3.2

#### DEC-003 · 交付形态选 Web
- **决策**:做 **Web 可视化界面**,CLI 保留为备用与调试入口
- **备选**:① 纯 CLI ② CLI + 可选 Web 外壳
- **理由**:① 科研 Agent 的目标用户是研究者而非工程师,纯 CLI 等于砍掉一半用户群;② 三模块的"资产增长"必须看得见,这是创新点的呈现方式
- **日期**:2026-10-28(原定纯 CLI,后推翻)
- **影响**:SRS `D-11`、`FR-F`、`NFR-11`

#### DEC-004 · Web 必须是薄壳
- **决策**:Web 层**不得实现任何业务逻辑**,只消费核心层事件流;`web/` 的 import 白名单 = 仅 Node 内置模块 + 事件总线
- **备选**:Web 层直接调 services
- **理由**:4 天内若两处都写逻辑,必然出现两套不同步的实现;且 Web 出 bug 会连带核心不可用,演示直接崩。薄壳保证 CLI 永远是可用的兜底
- **日期**:2026-10-28
- **影响**:SRS `D-12`、`NFR-12`、SDD §3.4.1

#### DEC-005 · 一条事件流两个渲染器
- **决策**:核心层只 `emit(event)`,**不知道谁在消费**;CLI 渲染器与 Web 渲染器消费同一份事件序列。事件类型固定 9 种
- **备选**:CLI 直接 print,Web 另接一套
- **理由**:一处定义事件两种展示;新增渲染器 = 加文件,不改核心逻辑
- **日期**:2026-10-28
- **影响**:SRS `D-13`、`FR-F1`、SDD §3.4.2-3.4.3

#### DEC-006 · Web 技术选型:零依赖零构建
- **决策**:后端用 Node 内置 `http` + SSE;前端用**单页 HTML + 原生 JS + 手写 CSS**;不依赖任何 CDN
- **备选**:① React + Vite ② Express + 前端框架 ③ Tailwind CDN
- **理由**:① 4 天内构建链是纯负债,没有构建就没有构建失败风险(现场最大的坑);② 事件是单向的,SSE 比 WebSocket 简单一个量级;③ 不依赖 CDN,断网也能打开页面
- **日期**:2026-10-28
- **影响**:SRS `D-14`、`AC-F4.1` `AC-F4.2` `AC-F4.5`

### 技术架构

#### DEC-007 · 语言与运行时
- **决策**:TypeScript + **Node 24 直接执行 `.ts`**(类型剥离,免构建)
- **备选**:① tsc 编译 ② tsx/ts-node ③ JavaScript
- **理由**:免构建省半天;形态与参考对象 Claude Code 一致。限制:不能用 `enum`/`namespace`,import 需带扩展名(对 4 天项目不是负担)
- **日期**:2026-10-27
- **影响**:SRS `D-08`、SDD §12.1

#### DEC-008 · 不引入 Agent 框架
- **决策**:不用 LangChain / AutoGen / Vercel AI SDK 的 agent 层。工具抽象、主循环、子 Agent、记忆**全部自研**
- **备选**:用现成框架快速出活
- **理由**:团队目标包含"系统学习 Agent 架构";用框架等于把学习点外包了
- **日期**:2026-10-26
- **影响**:SRS §1.1、`NFR-12`

#### DEC-009 · 不用 UI 框架
- **决策**:终端用 `chalk` + 原生 stdout,**不上 Ink/React**
- **备选**:Ink(React for CLI)
- **理由**:参考对象 Claude Code 的 `REPL.tsx` 单文件 875KB,说明其交互层极重;4 天项目里 UI 框架是纯负债
- **日期**:2026-10-27
- **影响**:SRS `D-09`、SDD §1.2 事实依据

#### DEC-010 · 知识库不引入向量检索
- **决策**:A 知识库用**两段式检索**:① 关键词粗筛(本地) ② **把清单交给便宜模型选**(LLM 筛选),不使用 embedding / 向量库
- **备选**:① 向量库(pgvector/Chroma) ② 纯关键词
- **理由**:**依据来自源码**——Claude Code 的记忆检索(`findRelevantMemories.ts:97-130`)全程无 embedding 调用,是把清单交 LLM 选。这省掉 embedding 成本 + 向量库依赖 + 索引一致性维护,且对术语密集的科研文本反而更准
- **日期**:2026-10-28
- **影响**:SRS `AC-A3.4`、SDD §7.4

#### DEC-011 · 知识存储可插拔
- **决策**:`KnowledgeStore` 做成接口,默认实现 `LocalMarkdownStore`(纯 Markdown + frontmatter);`KiwiFSStore` 列为 P2
- **备选**:直接绑死某个知识库产品
- **理由**:化解「kiwi 是否指 KiwiFS」这个未确认项。答"是"→ 加一个 adapter;答"否"→ 零改动
- **日期**:2026-10-27
- **影响**:SRS `D-06` §2.3

#### DEC-012 · Tool 失败模型
- **决策**:工具失败**只有一种表达**——回填 `is_error: true` + 错误文本,由模型自行决定是否重试。**取消** ok/recoverable/fatal 三分
- **备选**:框架判断错误是否可恢复
- **理由**:源码 `toolExecution.ts:469` 就是这么做。**框架没有足够信息判断"可不可恢复"**,把判断权交给模型更准
- **日期**:2026-10-28
- **备注**:这是对 SRS v2.0 的修正
- **影响**:SDD §4.1

#### DEC-013 · Tool 能力位 fail-closed
- **决策**:工具能力位(`isReadOnly` / `isConcurrencySafe` / `isDestructive`)漏写时按**最保守值**处理:不可写、不可并发、非只读
- **备选**:按最宽松值处理(开发者不写就当安全)
- **理由**:源码 `Tool.ts:757-769` 的 `buildTool` 默认值策略。安全靠默认值兜底,不靠开发者记得写
- **日期**:2026-10-28
- **影响**:SDD §4.1 `TOOL_DEFAULTS`

#### DEC-014 · 主循环三条红线
- **决策**:① **不读 `stop_reason`** 判断有无工具调用,改为遍历 content 块找 `type==='tool_use'`;② `tool_result` **必须全包在一条 user 消息内**,不与普通用户文本交错;③ 工具异常**不抛**,catch 后回填
- **备选**:按直觉实现(读 stop_reason、结果直接 push)
- **理由**:源码明确 —— `query.ts:553` 注释说 stop_reason 不可靠;`query.ts:1535` 说交错会导致 API 错误;`toolExecution.ts:469` 说异常要回填
- **日期**:2026-10-28
- **影响**:SDD §6.3

#### DEC-015 · 并发用分区策略
- **决策**:工具并发按 `partitionToolCalls` 语义:把**连续** `isConcurrencySafe` 的调用合成一批并发,遇不安全工具断开。上限从源码的 10 **收到 3**
- **备选**:全并行 / 全串行
- **理由**:全并行会撞 API 限流;全串行慢。分区是折中。上限收到 3 是照顾现场网络
- **日期**:2026-10-28
- **影响**:SDD §6.4

#### DEC-016 · 终止 reason 收为 5 种
- **决策**:`completed / max_turns / aborted / budget_exceeded / model_error`
- **备选**:照搬源码的 10 种
- **理由**:10 种是为超大代码库的精确诊断设计的;我们只需能区分"正常结束"与"哪类异常结束"。5 种够调试用
- **日期**:2026-10-28
- **影响**:SDD §4.2

#### DEC-017 · 子 Agent 只做 spawn,只回传末条文本
- **决策**:① 只做 spawn(从零上下文),**不做 fork**(继承父历史);② 子 Agent 结果**只回传最后一条 assistant 的 text 块**,不回传全文;③ 子 Agent 内禁用 `spawn_subagent`(防递归)
- **备选**:① fork + spawn 都做 ② 回传全部消息
- **理由**:① fork 是为 prompt cache 字节一致设计的,我们不做缓存优化,复杂度不值;② 源码 `agentToolUtils.ts:276` 只取末条 text,这是省 token 的核心手段
- **日期**:2026-10-28
- **影响**:SDD §10.1

### 三个模块的具体设计

#### DEC-018 · B 工具库分级
- **决策**:只承诺 **L1**(方法选型 + 参数填充);L2(多步 DSL)带人工确认做;**L3(自动生成分析代码)明确不做**
- **备选**:直接上 L3 让 LLM 写分析脚本
- **理由**:「论文里的方法描述」→「可执行代码」存在语义鸿沟,L3 质量完全不可控,失败即毁 demo。分级 = 把赌博变成可控工程
- **日期**:2026-10-27
- **影响**:SRS `D-04`、SDD §8.2

#### DEC-019 · B 模块用模板填充,不让 LLM 自由写代码
- **决策**:LLM **只负责抽取结构**(`MethodSpec`),代码由**固定模板**填进去
- **备选**:让 LLM 直接生成工具代码
- **理由**:即使 LLM 抽错参数,生成的工具也只是**参数不对**(被 zod 挡住),不会产生**任意可执行代码**。这是 L1 与 L3 的本质区别
- **日期**:2026-10-28
- **影响**:SDD §8.4

#### DEC-020 · B 模块成果必须过 smoke test
- **决策**:生成的工具必须通过 smoke test 才转 `active`;未通过标 `draft`,降级为"参数模板 + 人工填写"
- **备选**:生成即用
- **理由**:不验证就注册,等于把 demo 的稳定性交给 LLM 抽签。`tools doctor` 的通过率(≥60%)就是 B 模块的验收指标
- **日期**:2026-10-28
- **影响**:SRS `AC-B2.3` `AC-B2.4`、`A-7`

#### DEC-021 · C 技能库七节结构
- **决策**:技能固定七节:① 领域地图 ② 标准流程 ③ 方法→工具映射 ④ **常见失败模式** ⑤ 术语消歧 ⑥ 证据索引 ⑦ 负向约束。缺任一节标 `incomplete` 并拒绝加载
- **备选**:自由格式的 Markdown
- **理由**:技能最大的失败模式是**写成综述**。"失败模式"和"负向约束"两节是"判断力"与"综述"的分水岭 —— 综述型文档通常没有这两节
- **日期**:2026-10-27
- **评审话术**:「这份技能里,哪句话是只有踩过坑的人才知道的?」答不出来就是综述,打回重写
- **影响**:SRS `FR-C1`、SDD §9.4

#### DEC-022 · C 技能必须人工审核
- **决策**:技能生成后标 `needs_review`,**人工审核后**才能转 `active`
- **备选**:自动生效
- **理由**:技能是长期资产,错误的技能会**持续污染** agent 的判断。审核成本低(看一遍),污染成本高
- **日期**:2026-10-27
- **影响**:SRS `D-05`、`AC-C2.2`

#### DEC-023 · C 技能采用渐进式披露
- **决策**:① 常驻上下文的**只有元数据**(`name` + 一句话描述 + `whenToUse`),正文**懒加载**;② 清单总预算 = 上下文窗口的 **1%**(约 8000 字符),超预算时把次要技能压成纯名字
- **备选**:启动时把所有技能正文塞进 system prompt
- **理由**:**依据来自源码**——`loadSkillsDir.ts:100-105` 的 `estimateSkillFrontmatterTokens` 只统计三个字段,证明正文不进常驻上下文;`SkillTool/prompt.ts:21-40` 的 1% 预算策略。这条能让技能数量线性扩展而初始上下文不涨
- **日期**:2026-10-28
- **影响**:SDD §9.1、§9.3

### 协作与环境

#### DEC-024 · 源码参考纪律
- **决策**:`claude-code-main/` **绝不入库**,且**不复制其实现代码**,只学架构思想
- **理由**:该目录是 Claude Code 经 npm source map 暴露的源码镜像(1903 文件 / 29MB)。① 提交会污染仓库;② 仓库若转公开可能被判定侵权,黑客松取消资格;③ 学设计思想不侵权,抄代码侵权
- **日期**:2026-10-28
- **已执行**:`.gitignore` 排除,commit `b68ee54`
- **影响**:SDD §0.2

#### DEC-025 · 代理与环境
- **决策**:git/gh 必须显式配代理 `http://127.0.0.1:7892`(命令行工具不读 Windows 系统代理);项目路径含空格,所有脚本路径加引号
- **理由**:实测 —— 不配代理时 `github.com:443` 超时 21 秒;配代理后 1.3 秒成功。路径含空格会导致 `credential.helper` 的参数被截断
- **日期**:2026-10-27
- **影响**:SDD §12.3

#### DEC-026 · 纵向薄切片策略
- **决策**:三个模块**每个只做最小可用**,优先保证三层贯通;不追求单个模块做深
- **备选**:先把一个模块做完整再做下一个
- **理由**:4 天做不完三个完整模块。题目要求三个都是卖点,缺一个就少一个,所以"三个都薄"优于"一个厚两个没有"
- **日期**:2026-10-27
- **影响**:SRS `D-03`、SDD §13.1

#### DEC-027 · 因 Web 新增而让步的范围
- **决策**:砍**① 子 Agent 并行(精读改串行) ② 技能自动生成(改手写 1 个)**。不砍三模块、页码锚点、主循环、离线回放、Web 三面板
- **理由**:Web 约吃掉 1–1.5 天,必须有人让步。这两项是"评委看不见"的,而 Web 面板是"评委看得见"的
- **日期**:2026-10-28
- **影响**:SRS §3.3

## 四、维护约定

1. **谁决策谁记**,当天记,不留到"以后补"
2. **不删除**,推翻就在原条目标「已推翻」并加「演进记录」一行
3. **每条必须有"备选方案"** —— 没有备选说明没做取舍,那就不算决策
4. **每条必须有"理由"** —— "大家都这么干"不是理由
5. 影响需求的决策同步更新 `SRS.md` 的 `D-xx` 编号;影响实现的同步更新 `SDD.md` 对应章节
