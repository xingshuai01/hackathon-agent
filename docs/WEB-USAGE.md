# Web 页面使用说明

> 面向「第一次打开这个页面的人」。看完这一份就能把三个库跑出来,不需要先读 SRS/SDD。
> 页面本体零框架、零构建、零 CDN,所有数据来自本地存储的实时读取。

---

## 1. 启动

```bash
# 项目根目录
node src/main.ts web              # 真实模式:任务走 DeepSeek,需要 .env 里的 DEEPSEEK_API_KEY
node src/main.ts web --fake       # 演示模式:内置假 LLM,不花 token、不联网也能看完整流程
```

终端会打印实际地址(起始端口 `7777`,被占用时自动往后找,最多试 20 个):

```
· 已加载 .env(17 个变量)
Web 服务已启动:http://127.0.0.1:7777
· 模式:live
```

浏览器打开 `http://127.0.0.1:7777` 即可。按 `Ctrl+C` 停止。

> 只监听 `127.0.0.1`,同一台机器访问。要给别人看,先停掉再用
> `WEB_PORT=8080 node src/main.ts web` 起一个你想要的端口(仍建议只在本机共享)。

## 2. 页面布局:一屏四个区

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 顶栏:● 连接状态 + [任务输入框________] [运行]                    │
├──────────────────────────────────────────────────────────────────┤
│ ② 解析流水线:📄 PDF → ⚙ 解析 → 📚 知识库 → 🔧 工具库 → 📋 技能库   │
├────────────────┬─────────────────────────────────────────────────┤
│ ③ 三面板        │ ④ 过程流(SSE 实时)                              │
│  知识库 / 工具库 │  你说的话                                        │
│  技能库 + 计数   │  ⚙ 工具名 {参数}  ✓ 12ms · 结果摘要              │
│  点击卡片展开    │  📚 引用 p3f8a2c1#p7 (p.7)                       │
│  卡片右侧「删除」│  答:……(逐字流式)                                │
│                │  ■ completed · 3.2s · tokens 1.2k/0.4k · 工具 2 次│
├────────────────┴─────────────────────────────────────────────────┤
│ ⑤ 产物条(有 out/ logs/ 文件时才出现)                              │
└──────────────────────────────────────────────────────────────────┘
```

| 区域 | 说明 |
|---|---|
| ① 状态点 | 绿=已连上事件流;灰闪=连接中/重连中;页面出现「连接中断,正在重连…」横幅时,退避重连最多 10 次,之后点横幅手动重试 |
| ② 流水线 | 两个入口:**拖拽 PDF 解析**、**点三个库节点**看全量资产弹框 |
| ③ 三面板 | 数据来自 `GET /api/*`,数量与流水线节点上的数字同步;`run_end` 和解析完成后自动刷新,也可点右上 `↻` |
| ④ 过程流 | 每提交一次任务追加一个「运行块」,内含工具调用、技能加载、知识引用、答案、结束统计 |
| ⑤ 产物条 | 列出 `out/`、`logs/` 下最近 10 个文件(只展示文件名,不提供下载) |

## 3. 三条主流程

### A. 问一个问题(主循环)

1. 顶栏输入框键入任务,回车或点「运行」。
2. 请求 `POST /api/ask` **立刻返回 202**,页面不会卡住;真正的过程通过 SSE(`GET /events`)推回来。
3. 过程流里依次可能出现:

| 现象 | 含义 |
|---|---|
| `⚙ 工具名 {...}` + 转圈 | 工具开始执行 |
| 同一行变 `✓ 123ms · 摘要` / `✗ …` | 工具成功/失败(**失败不会中断**,模型会看到错误重试) |
| `📋 加载技能 xxx(命中关键词)` | C 技能库被命中,已注入上下文 |
| `📚 论文号 p.页码 · 摘要…` 小胶囊 | A 知识库被引用,**点它**会切到知识面板并展开对应卡片 |
| `🔧 生成工具 xxx [active]` | B 工具库新增/更新了工具 |
| 进度条 `step 3/7` | 长任务的阶段进度 |
| `✗ [stage] 消息` | 该阶段报错(例如缺 API Key),此时仍会收到 `run_end` |
| `■ completed · 3.2s · tokens a/b · 工具 n 次` | 本次结束统计 |

4. 同一时刻只允许一个任务:**上一个还没跑完时再提交会提示「上一次运行尚未结束」**(HTTP 409),不会排队、不会并发。

### B. 上传一篇论文(三库的唯一入口)

1. 把 PDF 拖到「拖拽论文 PDF 到这里」区域,或点「选择文件」(上限 50MB,只收 `.pdf`)。
2. 点 `▶ 开始解析`,按钮转圈期间**服务端在跑解析 + 入库 + 生成技能草案**。
3. 结束后弹「📄 解析结果」框,按三库分组展示:
   - **📚 知识库(A)**:本次抽出的原子知识页(类型 + 页码 + 原文引用)
   - **🔧 工具库(B)**:当前已就绪的工具名(方法抽取是独立流程,这里只报现状)
   - **📋 技能库(C)**:本次生成的技能草案 id 与「待人工补齐 N 项」
4. 关掉弹框,流水线三个节点闪一下,左侧面板与计数已刷新。

解析结果是**落盘的**:`knowledge/<paperId>/notes.md`(带页码锚点)、`skills/_drafts/<skillId>.md`(草案)。
同一篇论文重复上传会被判 `skipped`(已入库),不会重复抽;解析率 < 70% 的会被标 `quarantined` 并拒绝抽取。

> 解析 + 入库是**规则驱动**的,不需要 API Key;只有「问问题」这条主循环需要 LLM。

### C. 看/清理已有资产

- 点左侧 tab 在三个库之间切换;点流水线上的 `📚/🔧/📋` 节点弹出该库**全览**。
- 卡片单击展开/收起(知识页展开可见证据原文,技能展开可见 `whenToUse`)。
- **删除按钮**只出现在知识页与技能卡片右下角:
  - 知识页删除的是**整篇论文的全部知识页**(按 `paperId`),会重建索引
  - 技能删除时正式技能目录与 `_drafts/` 草案一起清
  - 工具**不可在页面删除**(它是提交进仓库的生成代码,删要走代码评审)
- 删除会先 `confirm` 二次确认,成功后自动刷新面板;接口幂等,删不存在的东西也返回成功。

## 4. 后端接口(想用 curl / 脚本时看这里)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/events` | SSE 事件流(9 种事件:`text_delta`/`tool_start`/`tool_end`/`skill_load`/`knowledge_hit`/`tool_generated`/`progress`/`error`/`run_end`) |
| POST | `/api/ask` | body `{"question":"..."}`,成功 202,已忙 409,空问题 400 |
| POST | `/api/ingest?filename=x.pdf` | body 是原始 PDF 字节(`Content-Type: application/pdf`) |
| GET | `/api/knowledge` | 知识页列表(含 `evidence.quote`) |
| GET | `/api/tools` | B 库工具列表 |
| GET | `/api/skills` | 正式技能 + 草案(`status: active/draft`) |
| GET | `/api/artifacts` | `out/`、`logs/` 文件清单 |
| DELETE | `/api/knowledge/<paperId>` | 删整篇论文的知识页 |
| DELETE | `/api/skills/<skillId>` | 删技能或草案 |
| GET | `/healthz` | 探活,返回 `{"ok":true}` |

命令行验收:

```bash
curl -s http://127.0.0.1:7777/healthz
curl -s http://127.0.0.1:7777/api/knowledge | head -c 300
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"question":"帮我算一下 1234 乘 5678"}' http://127.0.0.1:7777/api/ask
```

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 任务流里只有 `✗ [config] 缺少 DEEPSEEK_API_KEY` | `.env` 里没填 key。填上并重启,或改用 `node src/main.ts web --fake` 看流程 |
| 提交后马上出现 `■ 未执行` | 409:上一个任务仍在跑,等它 `run_end` 再来 |
| 端口不是 7777 | 7777 被占用,服务自动顺延(最多 +20);以终端打印的地址为准 |
| 状态点一直是灰/横幅反复出现 | SSE 断了。服务是否被杀?看终端;仍连着时点横幅可手动重连 |
| 面板是「暂无数据」 | 三库都还空。先拖一篇 PDF,或用 `node src/main.ts ingest fixtures/papers/xxx.pdf` |
| 上传报「PDF 为空或超过 50MB 上限」 | 体积超限或空文件;换文件重试 |
| 上传后状态 `quarantined` | 该 PDF 可解析页数占比 < 70%(扫描版?),按数据铁律不入库 |
| 解析后工具库还是 0 | 正常:工具由 B 模块方法抽取流程生成,不走 PDF 解析 |

## 6. 边界:这个页面故意不做的事

- 不做业务判断:重试、解析、校验、相关性筛选全在核心层,页面只把事件翻成 DOM。
- 不 import `src/services/**`、`src/agent/**`、`src/tools/**`,由 `npm run check:rules` 机械拦截。
- 不引入 React/Vue/Vite/Express/任何 CDN,断网也能打开。
- 不支持多人同时操作:它是**单机演示壳**,不是多用户服务。
