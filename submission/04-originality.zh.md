## 5. 真正属于我们的原创点

为了诚实,我们把「新的」和「组装得好的」分开说:

1. **用 quote 锚定出处,而不是相信模型给的页码。** 在两次插桩精读中(ReAct,arXiv 2210.03629,
   20 条;Transformer,arXiv 1706.03762,18 条),自报页码**只有 1/38 正确**,其余偏移为
   +1(二十八次)、+2(七次)、−4(一次)、−3(一次),不存在可用的算术补偿;而 quote 本身
   **38/38 可定位**。我们把这件事当作**让设计问题有答案的观察,而非错误率**:它回答的是
   「页码能不能直接采信」(不能),不是「模型有多大比例会报错」。因此系统从不采信模型给的页码,
   而是拿逐字 quote 在 PDF 自身的分页边界上反查——80 条知识页实测定位率 **99.7%–100%**。
   这把「模型说」变成了「原文说」。
2. **工具从论文里长出来。** 方法先被抽成带证据页的规格,再由确定性模板渲染成可运行工具,
   每个都配 smoke test。凡没有可信实现的,降级为「参数模板 + 人工填写」并记录原因,
   **绝不静默产出看着像对的代码**。
3. **修复「跑通了但结果错」的失效模式。** 审查中发现生成工具会接受不可能的输入
   (`success_rate(11,10)` 返回「110%」)。我们在模板层补了跨字段校验并加了回归测试。
   我们把这件事写进声明,因为「能跑」和「对」是两个不同的主张。
4. **技能的人工治理闸门。** 技能未经人工审核不得转 `active`,草案停在独立队列。
   共识性主张必须标注支持它的**独立论文篇数**,单篇做法必须写明「仅见于个别研究」。

## 8. AI 辅助开发声明

赛事期间我们使用了 AI 编码助手,和多数队伍一样。为了让这件事可审计而不是模糊:

- **人做决定**:产品方向、模块边界、六个冻结接口契约、数据铁律、决策台账里的每一处取舍。
- **AI 起草**:相当比例的实现代码、测试与文档。
- **每一处改动都过机械门禁**:`npm run typecheck`(0 错误)、`npm run check:rules`
  (自研检查器:依赖白名单、import 边界、禁用 `any`/`enum`/`namespace`)、
  `npm test`(378 用例 / 0 失败)。
- **每一处改动都有人审**:审查结论本身也入库为文档(`docs/REVIEW-2026-10-29.md`、
  `docs/REVIEW-B-2026-10-30.md`),包括我们**发现并修掉的缺陷**与**没修的已知缺口**。

我们主动写这一段,是因为评审会问「AI 是在做核心工作,还是只在增加复杂度与 token 消耗」。
在本系统里,AI 被放在能改变结果的位置——读论文、抽方法、蒸技能——外面套着由人设计的验证。

## 9. 合规情况

- 未使用任何受限或被禁止的库、模型 SDK、Agent 框架(由自动检查器执行,而非靠约定)。
- 不处理、不存储个人信息、保密信息、临床或许可受限数据。
- 不重新分发受版权保护的 PDF,仅保留短的、带署名的引用。
- SciencePal 用于**产品核心功能**:在主循环内以工具节点形式调用文献精读,其产物被流水线程序化消费。
  规则排除的是「**仅**用于文案、润色或制作 PPT」;我们的依据是**运行时集成**,不依赖任何文字辅助。
- 已知局限如实披露而非隐藏:表格与图片抽取当前为空;PDF 标题清洗不完善;
  1 个生成工具按设计降级为参数模板;5 个技能里 4 个仍是待审草案;
  页码结论覆盖**两篇论文共 38 条论断**,我们按「让设计问题有答案的观察」陈述,不当作实测错误率。
