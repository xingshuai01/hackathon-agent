## 项目名称

**Science Agent Coworker Hajimi** —— 一个读完论文会「长出」三个可复用库的科研 Agent。

*(一句话:读一篇论文应该留下点什么,而不只是留下一段聊天记录。)*

## 简介

本项目把论文转化成**三类可复用资产**,而不是答完就忘:

| 库 | 沉淀什么 | 回答什么问题 |
|---|---|---|
| **知识库** | 原子论断,每条都绑一个逐字 quote 与核实过的页码 | 「已知什么,那句话到底在第几页?」 |
| **工具库** | 从论文描述的方法里抽出来的可执行工具 | 「怎么做,我能直接跑吗?」 |
| **技能库** | 跨论文蒸馏的七节、可审核的技能文件 | 「该做什么,该避开什么?」 |

下次遇到同类任务,它直接用这些资产干活,而不是重读一遍文献。三个库会复利——
每多读一篇,Agent 就实用一分。

## 我们要解决的科研痛点

研究者缺的不是论文,是**读完留不下来的知识**。

我们把它当正确性问题(而非体验问题)来处理,具体是三个失效:

1. **论断丢失出处。** 组会前读 20 篇,六周后记得结论,却不记得出自哪篇、哪节、哪页,重推一遍
   要几小时。通用大模型会流利而自信地复述这个结论,但**无法核对**。对科研用途来说,
   不可验证的论断比没有论断更糟。
2. **方法只是被描述,从未变成可运行的。** 论文用散文写流程,把它变成可执行代码是纯手工活,
   做完即弃,于是同一个方法被每个课题组重新实现一遍。
3. **默会判断无法传递。** 真正决定方法能不能成的部分——阈值、前置条件、常见失败——待在
   经验者的脑子里,新人靠踩坑重新发现。

现有工具解决的是**检索**(在论文里搜)或**摘要**(给一段更长的答案),都没解决
「**带出处的积累**」:可供后续任务依赖的、持久且可审计的资产。

## 系统做了什么

```
PDF ──▶ 解析(段落 + 分页边界)
    ──▶ 知识库:4 篇 / 80 条原子知识页,每条带逐字 quote,
                页码由 quote 反查得到(不是模型自报)
    ──▶ 工具库:方法抽成规格 → 渲染成可运行 TypeScript 工具,每个自带 smoke test
    ──▶ 技能库:七节技能文件,草案先进人工审核队列
```

两个对评审重要的设计取舍:

- **页码从不取自模型输出。** 在两次插桩精读中(ReAct,arXiv 2210.03629,20 条;
  Transformer,arXiv 1706.03762,18 条),自报页码**只有 1/38 正确**,其余偏移为 +1(二十八次)、
  +2(七次)、−4(一次)、−3(一次),不存在可用的算术补偿;而 quote 本身 **38/38 可定位**。
  我们把它记为**让设计问题有答案的观察,而非错误率**:
  它回答的是「页码能不能直接采信」(不能),不是「模型有多大比例会报错」。
  因此知识库中每个页码都由逐字 quote 在 PDF 自身分页边界上反查得到,
  80 条知识页实测定位率 **99.7%–100%**。
- **工具是「长出来的」,不是人写的。** Agent 先抽出带证据页的方法规格,再由确定性模板渲染成工具。
  当前 5 个 active;凡没有可信实现的,降级为「参数模板 + 人工填写」,
  **绝不静默产出看着像对的代码**。

**SciencePal 在这条链路上不是装饰。** 主循环把 SciencePal 的 Agent 当成自己的一个工具节点
(`sciencepal_query`)来调,用于深度文献工作:SciencePal 负责精读、给出带逐字 quote 的论断;
我们的系统再校验这些 quote、把它们锚定到真实页码、并决定什么能进知识库。我们维护了两个自定义
SciencePal Agent——「Research Distiller」(`9e70403e-…`,本仓库所有实测 run 均由它执行)与
「论文精读官 / Paper Close Reader」(`ae5aaadf-…`,精读专用配置),分属两名成员账号;
每个 run 的归属以 `fixtures/runs/<runId>/manifest.json` 的 `agentId` 字段为准。

规则排除的是「**仅**用于撰写文案、润色文字或制作 PPT」。因此我们的依据**不落在任何文字辅助上**:
SciencePal 是产品主循环里的运行时组件,它的产物被流水线**程序化消费**,而不是被粘贴进文档。

## 目标用户与使用场景

**主要用户**

| 用户 | 处境 | 它给你什么 |
|---|---|---|
| 研究生 / 青年科研人员 | 进入新子领域,要读 20–50 篇 | 几个月后仍可查的、可引用级的知识库,带页码出处 |
| 课题组 PI / 资深研究者 | 带新人、写 related work | 可复用的方法与判断库,而不是一次性口头传授 |
| 系统综述 / meta 分析团队 | 大量论文筛读与信息抽取 | 可审计的抽取结果,每条陈述都能回到某一页 |

**具体场景**

1. **组会前。** 把本周论文拖进浏览器,每篇落 20 条原子论断进知识库,各自带来源页。
   之后问「这个结果是哪篇报的、在第几页」,答案几秒内可核对。
2. **复用方法。** 论文里描述的方法变成带 smoke test 的可运行工具,下个项目直接调用,
   而不是重新实现流程。
3. **交接经验。** 技能文件记录:什么时候该用这个方法、验收判据是什么、通常怎么失败。
   草案停在审核队列,**人工批准后**才转为 active。
4. **跨论文共识。** 技能里标 `evidence:3` 的条目意味着 3 篇独立论文支持;只有单篇支持的
   会明确写成「仅见于个别研究」,不许把一个实验室的习惯说成领域标准。

## 领域范围

方法对领域不敏感:它作用于**科学写作的结构**,而不是某个领域的数据。演示语料选 NLP/LLM
文献(ReAct、Transformer、BERT、RAG),因为这几篇公开、排版规整,评委可以自己逐条核对
每个 quote。流程里没有任何一步是机器学习专属的;同一条
「抽取 → 锚定 → 治理」路径对生物、健康、材料论文同样成立,而在那些领域,可追溯性只会更重要。
